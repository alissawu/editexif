# Verification

Production build/typecheck and 23 unit tests pass. Standard export readback checks camera/lens, capture dates/offsets, orientation, dimensions and exposure fields. Apple exports additionally compare all known and unknown Apple fields against the source, except the known per-shot identifiers resolved from the edited input. Unsupported writes fail closed. Standard GPS/editor/provenance groups are not cloned; unknown Apple payload can contain private vendor data.

The real iPhone 16 Pro HEIC supplied privately for testing reads Make Apple, Model and HostComputer iPhone 16 Pro, Software 26.6.2 and capture date October 8, 2026. Browser native-input checks produced JPEG and HEIC with the complete Apple payload and all existing shot IDs preserved. The photo is outside the repo and is not shipped as a template.

Current real-photo-import integration checks pass in Chromium. The plain picker has image/*,.heic,.heif and no capture attribute. It auto-fills model, custom lens, software, capture time, GPS/altitude, IANA timezone, filename and HEIC default. Tests edited software/date and disabled GPS after import, then exported JPEG and HEIC. Native readback confirms edits, intact non-ID Apple payload and regenerated reference IDs when the edited input genuinely has no IDs. Clear resets defaults. A stripped PNG import reports missing fields, leaves GPS off and exports using template fallback. Mobile layout has no overflow at 390 pixels. Network assertions found no uploads or external requests.

The dirty Picsart PNG fixture also contains original Apple shot IDs. Those MUST stay unchanged across exports. A separately stripped PNG fixture covers missing-ID regeneration. This distinction is intentional, not an exemption from the identifier rules. Six input IDs were independently checked in JPEG/HEIC output including slots absent from the selected template.

All 17 sourced metadata-only Apple carriers have passed native ExifTool validation. Scripts use -a -G -u reports and -validate/-warning/-error readback for browser exports, comparing known and opaque Apple values. Fixtures and generated reports are local/ignored. The scripts document required local fixture paths; the personal reference is never committed.

Timezone tests cover browser-default selection, common-first and complete Intl-supported IANA suggestions, GPS auto-selection, manual overrides, DST and fractional offsets. EXIF without GPS may supply only a UTC offset; it is retained as a fixed offset without inventing an IANA location. iOS suggestions use a curated release-date catalog including 26.x and 26.6.2; manually edited versions survive date/lens changes. iPhone exports default to HEIC even if an image picker returns JPEG.

No actual iOS/Android native-picker test has been run here. Desktop WebKit successfully imports the private native HEIC, including Software 26.6.2. Full Playwright iPhone 13 device emulation hangs at local-worker startup and times out after six minutes, before metadata import completes. A viewport-only WebKit export test and isolated emulation-setting checks are still under investigation. This is an unresolved compatibility issue, not a passing iOS Safari device test. Photo Library conversion, camera permissions, download behavior and limited-device memory require a real device. Missing metadata is observable; whether the OS stripped it cannot be proved from the delivered file alone. Native HEIC decode is tested, but unusual orientations, wide-gamut/HDR variants and maximum-size cases remain unverified.

HEIC outputs are single images, not Apple's 512-pixel grid layout. No HDR gain map, depth or Live Photo auxiliaries are emitted. Copied HDR-related MakerNotes do not create HDR data. JPEG/HEIC codec/container characteristics differ from native camera capture. Pixels are re-encoded to sRGB with white alpha flattening; exposure tags describe a source sample, not the scene. No detector or camera-origin guarantee. See MAKERNOTES.md for the binding limitations and feasibility research.
